# 敲木鱼：随身木鱼小工具

本说明和木鱼源码作为上一款应用保留。当前编译目标已切换为[掼蛋记分牌](guandan.zh_CN.md)，不能把当前构建产物当作木鱼固件；此前验证过的木鱼交付文件仍在本地 `build/delivery/` 目录。下文构建步骤适用于木鱼的源码配置，不适用于当前掼蛋的 `main/CMakeLists.txt`。

敲木鱼 1.0.0 把 AI Passport 变成离线木鱼计数器。按确定键即可敲击，播放短促的合成木鱼音效，木鱼随之移动，并显示功德加一的浮动动画。应用使用独立设计的暖纸色界面，不沿用硬件测试菜单。

目标硬件为 FoloToy AI Passport：ESP32-C3、8 MB Flash、无 PSRAM、240 × 320 竖屏和三个实体功能按键。无需 Wi-Fi、蓝牙连接、账号、云服务或额外接线。

## 启动与按键

每次开机，本次计数从零开始，自动敲击关闭。应用恢复上次保存的累计次数、音量和节奏。没有历史记录时，默认音量为 50%，节奏为每分钟 60 次。

| 按键操作 | 效果 |
| --- | --- |
| 按下确定键 | 立即敲击一次，本次和累计次数各加一；按住不连发。 |
| 短按上键 | 开启或暂停自动敲击；开启后经过一个节拍再敲第一下。 |
| 按住上键至少 500 毫秒后松开 | 在 60、90、120 次/分钟之间循环切换自动节奏。 |
| 短按下键 | 在 0%、25%、50%、75% 音量间循环；从默认 50% 开始，下一档依次是 75%、静音、25%、50%。 |
| 按住下键至少 500 毫秒后松开 | 打开“清空本次”确认框，并立即暂停自动敲击。 |
| 在确认框中按确定键 | 只清空本次次数，累计次数保留。 |
| 在确认框中按下并松开上键或下键 | 取消清空；等待 10 秒也会自动取消。 |

确认、取消或超时后，自动敲击都保持暂停。静音只影响声音，计数和动画照常进行。自动敲击期间，手动按确定键也会计数。次数达到 4,294,967,295 后保持该值，不会溢出归零。处理任务发生延迟时，自动模式最多补敲一下，不会连续补播积压的敲击。

右上角显示电量百分比；无法读取时显示 `--%`。手动模式下连续 30 秒没有功能键事件，背光从 70% 降为 10%；再次操作恢复到 70%，自动模式保持明亮。这只是背光调暗，不是深度睡眠。

## 保存与关机

本地 NVS 只保存累计次数、音量和节奏。本次次数和自动敲击的运行状态不恢复。

保存提示区分“已保存”和“未保存”。手动敲击或设置变更停止后，工作任务会在闲置约 1.5 秒时尝试保存。持续发生变更时，从本批首次变更开始约 30 秒尝试批量保存；写入失败后至少间隔 5 秒重试。这些是调度目标，不能保证断电或存储故障时完全不丢数据。

关机前，请先暂停自动敲击、停止按键，等待屏幕显示“已保存”。提前断电可能丢失最新尚未保存的累计次数或设置；应用不承诺突然断电后每次敲击都能保留。

如果 NVS 初始化失败，或已有记录的格式版本未知、长度不符、设置值无效，应用保留原有存储内容，改用内存计数，不会通过擦除 NVS 来恢复。“存储不可用”表示无法持久保存。声音和按键故障仍会与保存状态分开提示；声音故障不会停止计数。

## 开发与构建

应用在 `feature/muyu` 分支开发。本地 macOS ARM64 环境使用 `~/esp/esp-idf-v5.5.3` 中的 ESP-IDF v5.5.3、`~/.espressif` 中的托管工具和 Python 3.12。在仓库根目录激活环境：

```bash
source ./tools/activate-esp.sh
idf.py --version
./tools/validate.sh --static
./tools/validate.sh
```

版本必须为 `ESP-IDF v5.5.3`。完整验证包含仓库检查、主机测试、固件构建和合并镜像校验。命令成功与真实设备验收必须分别记录；本说明不代表某个具体构建已经通过验证。

无需 ESP-IDF 也可单独运行纯模型与输入测试：

```bash
cc -std=c11 -Wall -Wextra -Werror -Imain \
  tests/test_muyu_model.c main/muyu_model.c -o /tmp/test_muyu_model
/tmp/test_muyu_model
cc -std=c11 -Wall -Wextra -Werror -Imain \
  tests/test_muyu_input.c main/muyu_input.c -o /tmp/test_muyu_input
/tmp/test_muyu_input
python3 tools/generate_muyu_assets.py --check
```

测试覆盖计数、数值饱和、节拍调度、暂停和清空流程、短长按边界、重复按键边沿、缺失释放事件及唤醒防误触。素材检查验证所需字形清单与图片大小。主机 LVGL 渲染只用于预览应用布局和字体，不能证明真实屏幕显示、按键时序、扬声器输出或设备实际内存余量。

完成首次固件构建后，执行 `python3 tools/render_muyu_preview.py`，可复用已下载的 LVGL 9.5.0 生成十种状态的真实主机渲染截图，并检查字形、布局和连续动画内存。截图位于 `build/muyu-preview/screenshots/`，检查日志位于 `build/muyu-preview/validation.log`。

| 源文件 | 职责 |
| --- | --- |
| `main/muyu_model.c` | 纯计数、自动节奏、设置与确认框状态。 |
| `main/muyu_input.c` | 纯 PRESS/RELEASE 输入解释，不等待单击或双击识别。 |
| `main/muyu_ui.c` | 独立 LVGL 页面、状态提示、确认框与敲击动画。 |
| `main/main.c` | 启动、队列、界面所有权、合成音效、电量读取与 NVS 工作任务。 |
| `assets/fonts/` 与 `assets/images/` | 授权字体子集和原创木鱼图形，见[素材索引](../../assets/README.zh_CN.md)。 |

按键回调只记录时间戳并入队。音频和存储等慢操作在 I/O 工作任务中执行，界面调用持有 BSP 的 LVGL 锁。输入队列溢出时丢弃未完成手势并重新同步，避免把缺失的释放事件解释成长按。

## 固件安装

完整构建生成合并镜像：

```text
build/FoloToy-AI-Passport-full.bin
```

该文件用于从 `0x0` 烧录，不能换成仅包含应用的二进制文件。验证流程还会在 `build/firmware/<full-bin-sha256>/` 保留匹配的 ELF、MAP 和镜像文件；选定归档后可执行：

```bash
python3 tools/archive_firmware.py verify build/firmware/<full-bin-sha256>
```

确认目标设备并同意安装后，使用[本地玩法安装工具](https://ai-passport.folotoy.cn/tools/web-flasher/)选择已验证的合并镜像，或遵循仓库的[烧录与数据规则](../development/engineering/firmware-layout.zh_CN.md#烧录与已存数据)。合并烧录会替换当前应用，并可能重置 NVS，包括已保存的次数和设置。无需整片擦除，也无需先读回原固件；如需保留已有数据，请在选择完整刷新前另行保存。

## 真机验收与限制

本应用尚未完成真实设备测试。经同意烧录后，记录实际固件哈希，逐项检查：

1. 开机进入敲木鱼页面，检查全部中文、完整计数范围和确认框是否缺字、裁切。
2. 检查单次及快速按确定键、上/下短按和 500 毫秒边界附近的长按；按住一个键开机，松开后再正常使用。
3. 检查各档音量、静音、自动启停、全部节奏，以及清空确认的取消和超时。
4. 等待“已保存”后重启，检查累计次数和设置恢复，同时本次为零、自动敲击关闭。
5. 检查调暗与操作恢复、电量不可用时的反馈、运行内存余量及持续运行；如果使用场景关心功耗和续航，请在真实设备上测量。

音效是合成打击声，不是实体木鱼录音。音质、时序、屏幕效果、真实 Flash 保存、功耗和续航仍需真机验证。本版不包含网络服务、云同步、录音或导出功能。
